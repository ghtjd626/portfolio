# ADR-0007 — 웹 MVP 디자인 시스템: 손수 만든 CSS 토큰 (지금은 Tamagui 아님)

- **상태:** Accepted (웹 MVP 한정)
- **날짜:** 2026-07-27
- **관련:** ADR-0005(유니버설 전략), ux-principles.md

## What — 무엇을 결정하는가

웹 MVP의 UI를 **Tamagui가 아니라 CSS 변수 토큰 + 순수 CSS**로 구현한다(`app/globals.css`).

## Context — 배경

- ADR-0005는 *목표*로 **Tamagui 유니버설**(웹+모바일 공유)을 정했다.
- 그러나 Tamagui는 설정(컴파일러/Babel/프로바이더)이 무겁고 버전에 민감하다. 반면 이번 밤샘 목표는 **웹부터 실제로 동작하는 MVP**다.

## Considered Options

- **Tamagui 지금 도입 (A)** — 목표엔 맞지만 설정 리스크가 커 MVP 속도를 해친다.
- **손수 만든 CSS 토큰 (B, 채택)** — 디자인 토큰·다크·반응형·터치 타깃을 직접 통제.
- **범용 UI 라이브러리 (C)** — 빠르지만 "AI 양산물" 느낌 + 커스텀 통제력 약함(브리프 §동기와 충돌).

## Why — 근거

- **원칙을 그대로 구현.** ux-principles의 측정 기준(모바일 하단 내비, ≥44pt 터치, 라이트/다크, 즉시성)을 CSS 변수·미디어쿼리로 정확히 통제.
- **학습 리스크 격리.** Tamagui 도입을 모바일 네이티브 앱을 실제로 붙이는 시점(Phase)으로 미뤄, 웹 MVP 완성을 막지 않는다.
- **차별성 유지.** 범용 라이브러리 룩이 아니라 자체 토큰 시스템 → "직접 판단한" 흔적.

## How

- `:root` 토큰(색·반경·그림자·간격) + `prefers-color-scheme` / `[data-theme]` 라이트·다크.
- 반응형 셸: 모바일=상단바+하단 내비(thumb-zone), 데스크톱=사이드바.

## Trade-off / Consequences

- **좋은 점:** 즉시 동작·완전한 통제·의존성 최소.
- **감수하는 비용:** 이 CSS는 **웹 전용**이라 모바일 네이티브 앱과 컴포넌트를 공유하지 못한다. Tamagui 도입 시 UI 계층 재작성이 필요하다(단, 토큰 값·UX 규칙은 이전 가능).

## Counterfactual

- 만약 이번 목표가 "웹+네이티브 **동시** 출시"였다면, 고통스럽더라도 Tamagui를 먼저 세우는 게 옳았다. **웹 우선 MVP**라는 범위가 이 결정을 합리화한다. 네이티브 앱을 붙이는 Phase에서 ADR-0005로 수렴하며 이 ADR은 재검토된다.
