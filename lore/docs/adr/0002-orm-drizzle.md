# ADR-0002 — ORM으로 Drizzle 채택 (Prisma 대신)

- **상태:** Accepted
- **날짜:** 2026-07-27
- **관련:** ADR-0001(JSONB 동적 스키마), ADR-0003(로컬 SQLite), ADR-0004(모노레포)

## What — 무엇을 결정하는가

서버(Postgres) 및 향후 클라이언트(SQLite)의 데이터 접근 계층으로 **Drizzle ORM**을 채택한다.

## Context — 배경 / 결정 동인

- ADR-0001에 따라 데이터 모델은 **JSONB 중심의 소수 고정 테이블**이다. 무거운 관계형 매핑보다 **JSONB·생성 컬럼에 대한 세밀한 SQL 제어**가 중요하다.
- Local-first(ADR-0003)에서 클라이언트도 SQLite 계열을 쓸 가능성이 높다. 클라·서버가 **비슷한 쿼리 멘탈모델**을 공유하면 유지비가 준다.
- 배포는 서버리스/edge 가능성(Vercel). 콜드 스타트·번들에 민감.

## Considered Options — 검토한 선택지

- **Prisma** — 성숙한 DX, 강력한 마이그레이션, 큰 생태계. 그러나 자체 쿼리 엔진(런타임)·코드젠, 서버리스 콜드 스타트·번들 부담, JSONB/raw SQL 표현력에 제약.
- **Drizzle(채택)** — SQL-first, 경량, TS 스키마, 코드젠/런타임 엔진 없음, SQLite/Postgres 양쪽 지원.
- **Kysely** — 훌륭한 쿼리 빌더지만 스키마/마이그레이션 통합은 더 얇음.

## Why — 결정과 근거

**Drizzle를 택한다.**

- **JSONB·동적 작업에 유리.** SQL-first라 JSONB 연산·생성 컬럼·인덱스를 세밀히 제어. ADR-0001의 핫 필드 승격과 잘 맞는다.
- **클라↔서버 일관성.** Drizzle는 Postgres와 SQLite를 같은 스타일로 다뤄, local-first에서 로컬 SQLite 쿼리와 서버 쿼리의 멘탈모델이 이어진다.
- **경량·edge 친화.** 런타임 엔진·코드젠이 없어 콜드 스타트·번들에 유리.
- **Prisma DX 이점의 상쇄.** 우리 물리 스키마는 **의도적으로 최소**(동적 부분은 JSONB로 빠짐)라, Prisma의 "풍부한 모델 매핑" 이점이 이 프로젝트에선 크게 발휘되지 않는다.

## How — 어떻게 적용하나

- `packages/db`에 Drizzle 스키마(`record_types`, `records`, `tags`)와 쿼리 정의.
- 마이그레이션은 drizzle-kit. 물리 스키마가 안정적이라(ADR-0001) 마이그레이션 빈도 자체가 낮다.
- 클라이언트 로컬 스토어가 SQLite로 확정되면 동일 스키마 정의를 재사용 검토.

## Trade-off / Consequences

- **좋은 점:** SQL에 가까운 제어, 경량, 클라·서버 일관, 타입 안전(코드젠 없이).
- **나쁜 점 / 감수하는 비용:** Prisma 대비 생태계·툴링(스튜디오 등)이 젊다. 관계형 편의(자동 관계 로딩)는 더 수동적. 팀 온보딩 자료가 상대적으로 적다(1인 프로젝트라 영향 적음).

## Counterfactual — 반사실

- 데이터 모델이 **관계 중심의 풍부한 스키마**였다면 Prisma의 DX·관계 로딩이 더 값졌을 것이다. 우리 모델이 JSONB 중심·소수 테이블이라는 사실이 Drizzle을 정당화한다.
- Local-first에서 로컬 스토어가 SQLite가 아니게 되면(엔진 내장 스토어 등) "클라·서버 일관성" 근거의 무게는 줄지만, 나머지 근거(경량·JSONB 제어)만으로도 선택은 유지된다.
