# Roadmap — 단계별 로드맵

각 Phase는 **산출물(Deliverable)** 과 그 Phase가 무엇을 **증명(Proof)** 하는지를 함께 정의한다.
순서는 "세 요구(사용자 정의 스키마 · local-first · 멀티플랫폼 네이티브 UX)를 가장 빨리·확실하게 증명하는 순서"로 짜였다.

> **멀티플랫폼은 뒤에 붙이는 단계가 아니다.** 유니버설 UI(ADR-0005)라 컴포넌트를 한 번 만들면 웹·모바일에 함께 서고, 동기화는 Phase 1부터 양쪽 런타임을 검증한다. 즉 멀티플랫폼은 **로드맵 전체에 짜여** 있다.

> **📍 현재 상태:** **웹 MVP + 네이티브 앱 + 배포 준비 완료.**
> - Phase 0 완료 · Phase 2(사용자 정의 스키마) · Phase 3(뷰/UX + **네이티브 앱**) · Phase 4(프리셋) 대부분 달성.
> - **네이티브 앱**(`apps/mobile`, Expo Router + expo-sqlite)이 `schema-core`를 웹과 공유하며 동작 — 번들·타입·RN-web 렌더로 검증([ADR-0009](./adr/0009-native-app-stack.md)).
> - **Phase 5(배포)**는 설정·마이그레이션·가이드까지 준비 완료 — 계정 연결만 하면 배포([deploy.md](./deploy.md)).
> - **남은 것:** Phase 1(관리형 동기화 엔진 스파이크·라이브 동기화), Tamagui 유니버설 UI 수렴, 실제 배포·스토어 제출(소유자 계정).
>
> 자세한 경계는 [mvp-buildlog](./mvp-buildlog.md).

## Phase 0 — 기반 *(현재)*
**산출물**
- [x] 레포 씨앗, 비전/브리프/UX 원칙 문서, ADR 0001–0005
- [x] 모노레포 골격: `apps/web`(Next.js) + `apps/mobile`(Expo) shell + `packages/{schema-core, db, ui}` (Turborepo + pnpm)
- [x] `schema-core`: FieldDef 타입 + **Zod 컴파일 실구현** — 테스트 5/5 + strict 타입체크 통과
- [x] 물리 스키마(`record_types`, `records`(JSONB), `tags`, `record_tags`) — Drizzle로 구현
- [x] CI (lint · type-check · test) 골격, Docker Compose(로컬 Postgres)
- [ ] 웹·모바일 앱이 `schema-core`를 실제 import (스모크 완료; 실행 검증은 Phase 1 설치 시)

**증명** — 문제 정의·핵심 판단이 문서로 확정 + **핵심 논지 A(FieldDef→Zod)가 실제로 동작함을 테스트로 증명.** 종류를 코드가 아니라 데이터로 정의하고 런타임 검증까지 되는 걸 격리 실행으로 확인.

## Phase 1 — 동기화 엔진 스파이크 & 결정
**산출물**
- 후보(ElectricSQL / PowerSync / RxDB / Zero)를 **동적 스키마 + 웹·네이티브 양쪽 런타임** 기준으로 타임박스 프로토타입 비교
- 결정 + `ADR-0003` 확정(기준·결과·트레이드오프)
- 단일 하드코딩 종류로 오프라인 읽기/쓰기 + 동기화가 **웹(SQLite-WASM)과 모바일(expo-sqlite) 양쪽에서** 동작

**증명** — 최고 위험 결정을 근거로. **필수 관문(웹+RN 동기화)** 을 실증으로 통과.

---

## Phase 2 — 사용자 정의 스키마 MVP (유니버설)
**산출물**
- "기록 종류" 생성/편집(FieldDef 편집기)
- FieldDef → **동적 폼 자동 생성(Tamagui)**, 웹·모바일 양쪽에서 동작
- 기록 CRUD (오프라인 + 동기화, 낙관적 UI)

**증명** — **세 요구가 동시에 성립.** 코드 배포 없이 새 종류를 정의해, 웹·모바일 어디서든 오프라인 기록.

---

## Phase 3 — 뷰 · 쿼리 · 네이티브 UX 다듬기
**산출물**
- 목록/필터/정렬/태그, 종류별 뷰
- 핫 필드 인덱싱(생성 컬럼) + 성능 벤치마크
- 동기화 충돌 처리 UX(상태 노출)
- **모바일 네이티브 UX 1차**: 하단 내비·제스처(스와이프/당겨서 새로고침)·햅틱·Quick Add (ux-principles 게이트)

**증명** — 동적 스키마 위에서 실사용 가능한 조회·성능 + **모바일이 "웹 같지 않게" 느껴짐.**

---

## Phase 4 — 프리셋 도메인
**산출물**
- **가계부 · 할 일 · 일기**를 하드코딩이 아니라 **미리 정의된 기록 종류(템플릿)** 로 제공
- 가계부: 금액/카테고리/기본 통계, 할 일: 상태/마감, 일기: 감정/첨부

**증명** — 원하던 기능들이 메타 시스템의 **인스턴스로 공짜로** 나온다. 추상화가 값을 했다.

---

## Phase 5 — 통합 대시보드 · 검색 · 배포
**산출물**
- 여러 종류를 가로지르는 통합 대시보드/집계(데스크톱은 web 전용 밀도 레이아웃 허용)
- 전체 검색
- **웹 배포(Vercel + Neon)** + **모바일 배포(EAS Build, TestFlight/내부 트랙)**
- 실사용 시작, 케이스 스터디형 README 완성

**증명** — 파편화 해소(통합) + **웹·모바일 엔드투엔드 완성 + 실사용.** 성공 기준 충족.

---

## Phase 5+ — 의미 있는 확장 (선택)
- E2E 암호화(논지 C) · AI 시맨틱 검색/자연어 입력/자동 회고(논지 D, pgvector)
- 외부 통합(은행 CSV, 캘린더, GitHub) · 커리어/이력서 프리셋 · 습관/목표
- 앱스토어 정식 출시, 푸시 알림·위젯 등 네이티브 심화
