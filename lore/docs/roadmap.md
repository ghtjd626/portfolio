# Roadmap — 단계별 로드맵

각 Phase는 **산출물(Deliverable)** 과 그 Phase가 무엇을 **증명(Proof)** 하는지를 함께 정의한다.
로드맵의 순서는 "두 논지를 가장 빨리, 가장 확실하게 증명하는 순서"로 짜였다.

---

## Phase 0 — 기반 *(현재)*
**산출물**
- 레포 씨앗, 비전/브리프 문서, ADR 0001–0004
- CI (lint · type-check · test) 골격
- 물리 스키마 초안(`record_types`, `records`, `tags`)
- `schema-core` 패키지 스켈레톤(FieldDef 타입 + Zod 컴파일 시그니처)
- Docker Compose(로컬 Postgres)

**증명** — 문제 정의와 핵심 판단이 문서로 확정됨. "왜 이 프로젝트가 AI 양산물이 아닌가"가 성립.

---

## Phase 1 — 동기화 엔진 스파이크 & 결정
**산출물**
- 후보(ElectricSQL / Zero / RxDB / PowerSync)를 **동적 스키마 요구사항** 기준으로 타임박스 프로토타입 비교
- 결정 + `ADR-0003` 확정(기준·결과·트레이드오프)
- 단일 하드코딩 종류로 오프라인 읽기/쓰기 + 기기 간 동기화 기본 동작

**증명** — 최고 위험 결정을 하이프가 아니라 **근거로** 내렸다. (FDE식 리스크 조기 제거)

---

## Phase 2 — 사용자 정의 스키마 MVP
**산출물**
- UI에서 "기록 종류" 생성/편집(FieldDef 편집기)
- FieldDef → 동적 폼 자동 생성
- 기록 CRUD (오프라인 + 동기화)

**증명** — **두 논지가 동시에 성립**. 코드 배포 없이 새 종류를 정의해 오프라인으로 기록 가능.

---

## Phase 3 — 뷰 · 쿼리 · 충돌 해결 UX
**산출물**
- 목록/필터/정렬/태그, 종류별 뷰
- 핫 필드 인덱싱(생성 컬럼) 및 성능 벤치마크
- 동기화 충돌 처리 UX

**증명** — 동적 스키마 위에서도 **실사용 가능한 조회·성능**을 확보.

---

## Phase 4 — 프리셋 도메인
**산출물**
- **가계부 · 할 일 · 일기**를 하드코딩이 아니라 **미리 정의된 기록 종류(템플릿)** 로 제공
- 가계부: 금액/카테고리/기본 통계, 할 일: 상태/마감, 일기: 감정/첨부

**증명** — 원래 원하던 기능들이 메타 시스템의 **인스턴스로 공짜로** 나온다. 추상화가 값을 했다.

---

## Phase 5 — 통합 대시보드 · 검색 · 배포
**산출물**
- 여러 종류를 가로지르는 통합 대시보드/집계
- 전체 검색
- 배포(Vercel + Neon) + 실사용 시작, 케이스 스터디형 README 완성

**증명** — 파편화 해소(통합)와 **엔드투엔드 완성 + 실사용**. 성공 기준 충족.

---

## Phase 5+ — 의미 있는 확장 (선택)
- E2E 암호화(논지 C) · AI 시맨틱 검색/자연어 입력/자동 회고(논지 D, pgvector)
- 외부 통합(은행 CSV, 캘린더, GitHub) · 커리어/이력서 프리셋 · 습관/목표

---

### 진행 원칙
- Phase는 **vertical slice**로. 넓고 얇게 벌리지 않는다.
- 각 Phase 종료 시 데모 가능한 상태 + 결정 로그 갱신.
- 실사용 피드백(내가 직접)으로 다음 우선순위를 조정.
