# Discovery — 엔게이지먼트 브리프

> **프레이밍:** 이 문서는 "나를 고객으로 둔 FDE(Forward Deployed Engineer) 엔게이지먼트"의 discovery 산출물이다.
> 티켓을 받아 구현하는 게 아니라, 모호한 실제 니즈를 발굴하고 성공 기준을 정의하는 것에서 프로젝트를 시작한다.
> 이 문서가 존재한다는 사실 자체가 "AI로 대충 뽑은 프로젝트"와의 근본적 차이다.

## 1. 컨텍스트 / 이해관계자

- **고객 = 나 자신.** 2024년 4월부터 스타트업에서 프론트엔드 개발자로 일했고, 최근에는 FDE에 가까운 일(엔드투엔드로 문제를 받아 완성하는 일)을 하고 있다.
- **동기:** AI가 발달하면서 "프론트만 한다"는 정체성보다, 최신 스택을 가리지 않고 써서 **하나의 완성된 나만의 프로젝트**를 엔드투엔드로 책임지는 역량을 증명하고 싶다.
- **사용 맥락:** 매일 쓰는 개인 도구. 지하철·비행기·집 등 네트워크가 불안정한 환경 포함.

## 2. 해결하려는 진짜 문제

내 삶의 기록은 지금 이렇게 흩어져 있다:

| 기록 | 현재 도구 | 불만 |
|---|---|---|
| 가계부 | 뱅킹 앱 / 스프레드시트 | 다른 기록과 단절, 커스터마이즈 불가 |
| 일기 | 메모 앱 | 검색·구조화 약함, 민감 데이터 클라우드 종속 |
| 할 일 / 일정 | Todo 앱 / 캘린더 | 회고·집계로 이어지지 않음 |
| 커리어 / 이력서 | 문서 파일 | 매번 처음부터, 원천 데이터 없음 |

**핵심 통증 3가지:**

1. **파편화** — 도구가 앱마다 따로라 "내 삶 전체"를 한 곳에서 보고 집계할 수 없다.
2. **소유권 부재** — 민감한 일기·가계부가 남의 서버에 있다. 내 데이터가 내 것이 아니다.
3. **경직성** — 앱이 정해준 필드만 쓸 수 있다. "내 입맛대로" 기록 구조를 바꿀 수 없다.

## 3. Jobs To Be Done

- "무엇이든 **내가 원하는 구조로** 기록하고 싶다." → 사용자 정의 스키마
- "네트워크와 무관하게 **즉시** 기록하고, 여러 기기에서 이어보고 싶다." → local-first + 동기화
- "흩어진 기록을 **한 화면에서 집계·검색**하고 싶다." → 통합 대시보드 / 전체 검색
- "내 데이터를 **내가 소유·백업·이전**하고 싶다." → 데이터 소유·export

## 4. 제약 (Constraints)

- **1인 · 파트타임 개발.** 과설계는 곧 미완성. 범위를 좁게, 깊이를 확보.
- **실사용이 성패의 기준.** 내가 매일 안 쓰면 실패한 제품이다. → UX·즉시성이 타협 불가.
- **프라이버시.** 일기·가계부는 민감. 데이터 소유가 기본값.
- **포트폴리오 가치.** 결정마다 What/Why/How가 남아야 한다. 완성보다 **판단의 서사**가 우선.

## 5. 성공 기준 (측정 가능하게)

- **[제품]** 내가 최소 4주 연속 매일 Lore에 기록한다 (기존 도구 최소 2개를 대체).
- **[논지 A · 사용자 정의]** 코드 배포 없이, UI에서 새로운 "기록 종류"를 정의하고 바로 기록할 수 있다.
- **[논지 B · local-first]** 비행기 모드에서 기록/수정이 즉시 되고, 온라인 복귀 시 다른 기기와 충돌 없이 동기화된다.
- **[포트폴리오]** 모든 핵심 결정이 ADR로 존재하고, README만 읽어도 문제→판단→구현의 서사가 전달된다.

## 6. Non-goals (지금은 안 한다)

- 다중 사용자 · 협업 · 공유 (단일 사용자에 집중; 멀티테넌시는 반사실로만 문서화)
- 모바일 네이티브 앱 (PWA로 대체; 네이티브는 확장 여지)
- 실시간 협업 편집
- 수익화 · 마케팅
