# UX Principles — 사용자 경험 원칙

> UX는 이 프로젝트의 **1급 목표**다(discovery §성공 기준, ADR-0005).
> 모바일은 Toss·배민 수준의 네이티브 경험을, PC는 넓은 정보 밀도를 목표로 한다.
> 이 문서는 "예쁜 화면"이 아니라 **측정 가능한 사용성 기준과 설계 규칙**을 정의한다.

## 왜 UX가 논지만큼 중요한가

- 성공 기준이 "**내가 매일 쓴다**"이다. 마찰이 크면 안 쓰게 되고, 안 쓰면 실패한 제품이다.
- 나는 프론트엔드/FDE로서 **UX 품질 자체가 증명하려는 역량**이다. → 이 문서는 포트폴리오의 일부다.
- local-first가 즉시성을 가능케 하지만, **그걸 UX로 살리는 건 별개의 설계**다.

## 핵심 원칙

1. **오프라인·즉시성이 기본값.** 저장/수정은 스피너 없이 즉시 반영(낙관적 UI), 실패 시 조용히 롤백. local-first를 UX로 번역한다.
2. **모바일 우선 정보구조.** 한 손 조작·엄지 도달 영역(thumb zone)·하단 내비게이션. 핵심 액션은 화면 하단에 둔다.
3. **최소 마찰 입력.** 빠른 기록(Quick Add), 스마트 기본값(오늘 날짜·최근 종류·자동 태그), 최소 탭. "몇 탭 안에 끝"이 목표.
4. **네이티브 제스처 & 전환.** 스와이프 액션·당겨서 새로고침·부드러운 화면 전환/공유 요소 전환. 모바일에서 "웹 같지 않게".
5. **명확한 피드백.** 햅틱·마이크로 인터랙션·토스트로 모든 액션에 반응을 준다.
6. **동기화 상태를 1급 UI로.** 오프라인 표시, 동기화 진행/완료, 충돌 해결을 사용자가 이해할 수 있게 노출.
7. **일관된 디자인 토큰.** 색·타이포·스페이싱·모션·라운드를 토큰(Tamagui 테마)으로. 라이트/다크 완전 대응.
8. **접근성 기본 탑재.** 대비 WCAG AA, 터치 타깃 ≥44pt, 스크린리더 레이블, 폰트 스케일·다이나믹 타입 대응.
9. **점진적 정보 밀도(반응형 정보구조).** 모바일은 압축·집중, 데스크톱은 확장·다중 패널. 단순 리사이즈가 아니라 정보구조 자체를 반응형으로.
10. **성능 예산.** 상호작용 응답 체감 <100ms, 리스트 가상화, 이미지 지연 로드.

## 측정 기준 (성공 판정)

| 지표 | 목표 |
|---|---|
| 핵심 기록(예: 지출 1건) 완료까지 탭 수 | 모바일 3탭 이내 |
| 저장 후 화면 반영 체감 | 즉시 (스피너 없음) |
| 오프라인에서 기록/수정 | 100% 동작 |
| 색 대비 | WCAG AA 통과 |
| 최소 터치 타깃 | ≥ 44×44pt |
| 라이트/다크 | 전 화면 지원 |

## 디자인 시스템 방향

- **Tamagui 테마 + 토큰**으로 유니버설 컴포넌트(웹/네이티브 동시). 플랫폼별 탈출구는 UX가 요구할 때만.
- 컴포넌트는 `packages/ui`에 헤드리스 지향으로, 도메인/화면과 분리.
- 모션은 절제되고 목적 있게(방향·연속성 전달). 화려함보다 **매끄러움**.

## 참고한 사용성 감각 (벤치마크)

- **Toss** — 즉시성, 절제된 모션, 명료한 정보 위계, 스트레스 없는 흐름.
- **배민** — 빠른 탐색·주문 흐름, 최소 탭, 친근하고 일관된 톤.

*이 원칙들은 각 Phase의 UX 게이트로 쓰인다 — 새 화면은 이 기준을 통과해야 "완료"다.*
